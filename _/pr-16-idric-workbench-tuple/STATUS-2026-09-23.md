# Status on 2026-09-23

Current Cat Food `main` has absorbed much of the direction of PR #16 through later work, but not by merging this branch.

Current `main` already:

- distinguishes host workbench provisioning from Android runtime delivery;
- builds Grease, Idriç, Idric-Net, Fieldmouse, ICU, IB, Ithon, and IR on the host path;
- keys several rebuild decisions to source/compiler revisions;
- initializes IB recursively;
- exposes stable commands for the maintained host tools;
- keeps Idriç's pinned toolchain/runtime available during Idriç-dependent builds;
- has a much larger target, package, Android-delivery, and follower-evidence architecture than existed when #16 was written.

For that reason, the archived branch should not be rebased and merged wholesale.

Ideas from #16 that remain worth deliberate comparison with current `main` include:

- whether the present build system should emit one comprehensive, machine-readable exact-tuple receipt analogous to `core-build.tsv`;
- whether source-head and GitHub-release freshness should again be a first-class Cat Food check and receipt, and for which projects;
- whether current stable-command wrappers preserve enough runtime provenance to prove that Idriç-generated programs use the intended pinned Chez runtime;
- whether current IB acceptance should exercise more than the present smoke program;
- where Cat Food's construction/provenance boundary should end and ai-ci's independent acceptance boundary should begin.

A follow-up issue owns those questions. This directory exists so that issue can start from the historical implementation and rationale without keeping PR #16 open.
