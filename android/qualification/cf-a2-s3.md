# Installed byte and evidence boundary

This work resumes the retained APK consumer on current Cat Food main. A schema
is a declaration format; it does not authorize acceptance. `check.sh schema`
inspects v2/v3 declarations. `check.sh receipt` verifies the v3 installation
bindings. `check.sh authorize RECEIPT TARGET INSTANCE installation` additionally
re-observes mutable device facts and execution-dependency selection. No imported
inventory row authorizes a current cell. Version 2 receipts remain historical
and are inspected with `schema`; the installer preserves them when replacing
their installation record. It carries no launch/runtime/physical result forward.

Version 3 binds the exact declared source/package, plan, profile oracle, target,
local instance, model/product/ABI and firmware; whole installed content, every
launcher and declared runtime/package dependency; and installation procedure.
The content authority is a freshly reconstructed tree from the exact pinned
archive/file, including non-entry files, directory membership and symlink
identity. Receipt-provided hashes alone cannot establish the expected payload.
DEX/JNI wrappers are independently reconstructed from the manifest. Cached
archives are rehashed before and after extraction. Entry-point existence and a
matching archive SHA alone are insufficient. Changed installed content fails
before package management or legacy-link cleanup; it is not silently repaired
and relabeled PASS. An exclusive workspace lock blocks concurrent installation
and interrupted lock reuse. Removal of a retained lock is an explicit recovery
action, not automatic acceptance.

`evidence_scope=synthetic` identifies overrides/host fixtures. A real observed
Android installation has `physical-observation`; that is still installation,
not a passing physical runtime claim. Local aliases/model properties are
consistency observations, not hardware attestation. Copying a local alias does
not authenticate a handset. Imported inventories remain `unconfirmed` even
when their text says `receipt:PASS`.

The Reddit procedure checks installation bytes and current facts before making
an evidence directory and after executing the unchanged launcher. It records
fresh procedure, installation-receipt and log digests at the observed scope.
The installation receipt stays unchanged. Unsigned runtime logs cannot
authenticate their own execution, so historical/local launch/runtime/emulator/
physical PASS declarations cannot authorize cells. They remain unverified
until an independent execution witness is available. Likewise an invented
build PASS is rejected at the producer boundary. This is deliberate blocked
authorization, not a claim that current host fixtures proved device behavior.

The C67 runtime recorder rehashes the selected native probe after execution,
re-observes firmware/identity, rejects ambiguous receipts and retains procedure,
manifest and receipt digests. Its result is explicitly an observation.

APK admission retains the fixed independent AICI v2 decision/witness consumer,
actual-byte inspection delegated to AICI and copied-byte revalidation/sealing.
Cat Food does not duplicate signer or compiler policy. Real canonical Crystal
APK fixtures are used for public denial. Positive authenticated admission and
post-admission publication race qualification remain blocked until the S4
independent deployment exists. No deployment was created for these tests.

## Dependency boundary

S1's extended invariant corpus and S2's new authoritative plan/profile model
are independent predecessor work. This branch tests the current corpus and
binds the existing plan/profile files; it does not claim to integrate unseen
successor contracts. The integration must refresh these bindings against exact
verified predecessor outputs. S4's independent producer deployment and
execution qualification are unavailable. APK positive admission and replayed
runtime/physical authorization remain blocked. No fresh device run, release,
activation, merge or production publication is claimed.

## Reproducible host evidence

`tests/android-content.pi` is checked/executed by the pinned Ithon frontend.
Its synthetic acquisition/property/probe programs execute the recorded Grease
artifact, never a substitute shell. The stage-zero POSIX boundary remains
necessary because it validates Grease's own delivery before Grease is present.
`tests/android-content-mutations.pi` removes payload authorization, mutable-fact
observation and the Reddit runner body independently. Each must fail at its
corresponding semantic case, not merely at an unrelated earlier rejection.
The exact original byte-substitution case runs against audited main and records
its false positive; the repaired source rejects it and checks no installed-state
change. Synthetic DEX/JNI fixtures do not claim ART/JNI execution.

Ithon frontend limits encountered: defaults at call sites, `raise`, dynamic
subscript assignment, string multiplication, untyped foreign-method results and
boolean combinations required explicit typed boundaries or supported method
calls. No unchecked Python execution was used to bypass those failures.
