# Android physical acceptance bundles

The physical phone and tablet are runtime targets. They should not clone source repositories or build projects.

This directory builds two self-contained archives:

- `catfood-phone-acceptance-<commit>.tar.gz` for the ARMv7 phone;
- `catfood-tablet-acceptance-<commit>.tar.gz` for the AArch64 tablet.

Each archive contains the exact already-built upstream artifacts needed by the current physical-device queue plus one runner. On the device, extract the archive and run:

```sh
./run.sh
```

The runner executes every selected case even if an earlier case fails. Each case has its own log, and the final `summary.tsv` records PASS/FAIL independently. Receipts are also packed into one tarball at the end.

## Current phone queue

- Cat Food legacy-command migration and arbitrary-user-command protection from the `android/minimal-tablet-bootstrap` line;
- current ARMv7 Grease readable syntax;
- the current Grease/IB mapped-index program using `openat`, `mmap`, `msync`, and `munmap`;
- cloud-storage `google-drive-unzip --help` without credentials;
- Ike dependency/recipe execution through the Android shell boundary;
- the published direct DEX/JNI Reddit command bundle through Android `app_process`.

The PowerVR phone hardware gate is not repeated here because its exact producer/package already has physical phone evidence. The current accelerometer presentation is likewise already physically accepted.

## Current tablet queue

- the same Cat Food migration/protection fixture;
- the currently published AArch64 Grease runtime smoke;
- cloud-storage `google-drive-unzip --help` without credentials;
- Ike dependency/recipe execution;
- the published direct DEX/JNI Reddit command bundle;
- the packaged PowerVR EGL/GLES acceptance runner against the physical tablet vendor driver.

The tablet Grease package remains the exact artifact currently published for `grease#14`; it is older than the current phone Grease line, so the newer mmap-based IB proof is deliberately not projected onto that artifact.

## Evidence boundary

The bundles do not turn cloud builds, checksums, package extraction, emulator runs, or one device into evidence for another stage or target. Each case names its exact producer revision in `queue.tsv` / `payloads.tsv`, and physical execution is the only new evidence generated by `run.sh`.

The Cat Food migration test uses the exact `android/install.sh` and `android/check.sh` carried by the bundle commit. It operates only in a temporary isolated prefix: first it proves that old Cat Food-owned links/wrappers can be replaced, then it proves that a regular user-owned command is refused and left unchanged.
